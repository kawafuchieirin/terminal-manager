# Cornix LP（Vial キーマップ）

分割キーボード **Cornix LP** のキーマップを Git 管理する。
[Vial](https://get.vial.today/) が書き出す `.vil`（JSON）をリポジトリ側に置き、`jq` で整形して
「どのレイヤーのどのキーを変えたか」が diff から読める状態に保つ。

`~/.config/` へのリンクは張らない。`.vil` は Vial の GUI から読み込むファイルで、
常駐プロセスが参照する設定ファイルではないため、`setup.sh` / `uninstall.sh` の対象外。

## ファイル構成

| パス | 内容 |
|------|------|
| `keymaps/*.vil` | Vial で保存したキーマップ（整形済み JSON） |
| `format-vil.sh` | `.vil` を `jq` で整形するスクリプト |
| `test-format-vil.sh` | `format-vil.sh` のテスト |

## 前提

`jq` **1.7 以降**が必要（`setup.sh` の Homebrew formula に含まれる。単体なら `brew install jq`）。

1.7 より前の `jq` は整形時に数値リテラルを作り直すため、`.vil` の `uid`（64bit 整数）が
指数表記に丸められてファイルが壊れる。`format-vil.sh` はバージョンを検査して、古い場合は
整形せずエラーで止まる。macOS 15 以降は `/usr/bin/jq`（1.7 系）が同梱されている。

## キーマップを保存する

1. Vial で **File → Save current layout** を選び、`cornix-lp/keymaps/` に保存する
   （ファイル名は `cornix-lp.vil` のように固定しておくと diff が追いやすい）
2. 整形する

   ```sh
   ./cornix-lp/format-vil.sh
   ```

3. コミットする（pre-commit が入っていれば 2 は省略できる。[pre-commit](#pre-commit) 参照）

   ```sh
   git add cornix-lp/keymaps/cornix-lp.vil
   git commit -m "feat: Fn2レイヤーに矢印キーを追加 (FW v1.8)"
   ```

## キーマップを読み込む

1. Vial でキーボードを接続する
2. **File → Load saved layout** で `cornix-lp/keymaps/*.vil` を選ぶ
3. 反映されたキーを実機で確認する

Vial は読み込んだ内容をキーボードへ即時書き込む。手元の設定を上書きしてよいかを確認してから実行する
（現状を残したい場合は先に **Save current layout** で別名保存しておく）。

## 整形スクリプト

```sh
./cornix-lp/format-vil.sh                 # keymaps/ 配下の .vil をすべて整形
./cornix-lp/format-vil.sh path/to/x.vil   # 指定したファイルだけ整形
./cornix-lp/format-vil.sh --check         # 整形せず、未整形なら終了コード 1
./cornix-lp/format-vil.sh --help          # ヘルプ
```

やること・やらないことを明確に分けている。

- **やること**: `jq --indent 2` で改行・インデントを入れる（キーコードが 1 行 1 個に並ぶ）
- **やらないこと**: キー割り当て・レイヤー構成・`uid` などの値の変更、キーの並べ替え

安全側の作りとして、整形前後の JSON を正規形（`jq -S -c`）で比較し、一致しない場合は
**書き戻さずにエラーで止まる**。JSON として壊れているファイルも同様に書き換えない。

終了コードは「変更なし / 整形した」= 0、「`--check` で未整形を検出」= 1、
「整形失敗（書き戻していない）」= 2。

### テスト

```sh
./cornix-lp/test-format-vil.sh
```

整形の冪等性、`uid` のリテラル保持、`layout` が変化しないこと、`jq` 未導入・旧バージョン時の
エラー、壊れた JSON を書き換えないことを検証する。

## pre-commit

`.pre-commit-config.yaml` の `format-vil` フックが、コミット対象の `.vil` を自動整形する。
Vial から保存したままの 1 行 JSON をコミットしようとすると、整形されてコミットが中断するので、
`git add` し直してからコミットする。

```sh
pre-commit run format-vil --all-files   # 手動で全ファイルに実行
```

`jq` が未導入の場合は、導入方法を含むエラーを出してコミットを止める（黙って素通りはしない）。

## 別の Cornix LP へ設定を移す

**ファームウェアのバージョンを揃えてから読み込む**のが前提。レイヤー数・キーマトリクス・
対応機能はファームウェアに依存するため、バージョンが違うと読み込めない／意図しないキーに
割り当たることがある。

1. 移行元で **File → Save current layout**（このリポジトリの `.vil` が最新ならそれを使う）
2. 両方の個体のファームウェアを確認し、**同じバージョンを両方に書き込む**
3. 移行先で **File → Load saved layout** して `.vil` を読み込む
4. 全レイヤーを実機で確認する（特にレイヤー切り替え・エンコーダー・コンボ）

### ファームウェアバージョンの確認と記録

Vial の画面からはファームウェアのバージョン文字列が読めないことがあるため、
**書き込んだファームウェアのバージョンを自分で記録しておく**。

- 配布ファームウェアを使っている場合: 入手元のリリースタグ（`v1.8` など）
- 自分でビルドしている場合: ビルド元のコミットハッシュ

記録先はコミットメッセージ（次節）。どの `.vil` がどのファームウェアで保存されたものかが
履歴から辿れる状態を保つ。

### 読み込めないときに確認すること

- **別のキーボード用の `.vil` ではないか**: `.vil` の `uid` はキーボード定義に紐づく。
  Vial が別キーボード向けと判断すると読み込みを拒否する
- **ファームウェアのバージョン差**: レイヤー数やマトリクスが変わっていると、読み込めても
  キーがずれる。2 の手順でバージョンを揃える
- **ファイルが壊れていないか**: `jq empty cornix-lp/keymaps/cornix-lp.vil` でパースを確認する

## コミットメッセージの運用

キーマップを変更したコミットには、**そのとき書き込んでいたファームウェアのバージョンを
末尾に書く**。後から「どのファームウェアで保存した `.vil` か」を履歴だけで判別できるようにするため。

```
feat: Fn2レイヤーに矢印キーを追加 (FW v1.8)
fix: 左右の親指キーの入れ替わりを修正 (FW v1.8)
chore: ファームウェアをv1.9へ更新しキーマップを再保存 (FW v1.9)
```

- 型（`feat:` / `fix:` など）はリポジトリ共通の規約に従う（[.claude/rules/commit-convention.md](../.claude/rules/commit-convention.md)）。
  キー・レイヤーの追加は `feat:`、意図どおり動いていないものの修正は `fix:`
- ファームウェアを更新して `.vil` を再保存しただけのときは `chore:` を使い、
  本文に「どのバージョンから上げたか」を書く
- 既存キーの割り当てを別の操作に変える場合は、本文に `注意:` として旧割り当てと新割り当てを書く
