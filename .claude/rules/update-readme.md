# README 自動更新ルール

設定ファイルやスクリプトを変更した場合、README を実態に合わせて最新化すること。

## ドキュメントの階層

- **ルートの `README.md`**: 全体の索引。概要・クイックスタート・ドキュメント索引・ファイル構成・
  `setup.sh` の処理内容・ルート直下の設定（pre-commit / リリース）・設計方針まで。
  **個々のツールの詳細（設定値一覧・キーバインド表・使い方）はここに書かない**。各 README へリンクする。
- **各ディレクトリの `README.md`**: そのツールの詳細。設定値とその意図、全キーバインド、使い方、注意点。

| ディレクトリ | README | 書く内容 |
|-------------|--------|---------|
| `wezterm/` | `wezterm/README.md` | フォント・外観・タブバー・ペイン・挙動・パフォーマンスの各設定値と意図、全キーバインド、リロード方法 |
| `zsh/` | `zsh/README.md` | `.zshrc` の読み込み順、プラグインと連携ツール、キーバインド、`kb` コマンド、履歴、環境変数、エイリアス全表、関数 |
| `zsh/hidden/` | `zsh/hidden/README.md` | 環境固有設定・シークレットの扱い、会社 Mac / 個人 Mac の使い分け |
| `starship/` | `starship/README.md` | プロンプトの構成順・各セグメントの設定・カスタマイズ方法 |
| `pet/` | `pet/README.md` | 呼び出し・登録・編集・共有、`select.sh` の仕組み |
| `lazygit/` | `lazygit/README.md` | 設定値と意図、主なキー |
| `gh-dash/` | `gh-dash/README.md` | 導入手順（`setup.sh` 対象外）、日常操作、`config.yml` の内容 |

新しいツールを追加したら、そのディレクトリに README を作り、ルート `README.md` の
「ドキュメント索引」と「ファイル構成」に 1 行ずつ足す。

## 更新手順

1. 変更したファイルの内容を読み取る
2. 対応するディレクトリの README を実態に合わせて更新する
3. 索引・ファイル構成・`setup.sh` の処理内容に影響する変更なら、ルート `README.md` も更新する
4. 存在しない機能の記述は削除し、新規機能はセクションに反映する

## 注意事項

- エイリアス一覧は `zsh/aliases.zsh` の実際の内容からテーブルを生成する（推測で項目を増やさない）
- `setup.sh` でインストールされるパッケージ一覧は実際のスクリプトと一致させる
- WezTerm のキーバインド表は `wezterm/wezterm.lua` の `config.keys` を漏れなく反映する
- キーを変更したときは、設定ファイル側の `kb:` コメントも更新する（`kb` コマンドがこの行を読み取る）
- ルート README と各 README で同じ表を二重管理しない。詳細は各 README、ルートはリンクのみ
- 過度に冗長にせず、簡潔にまとめる
